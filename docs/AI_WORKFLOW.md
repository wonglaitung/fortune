## 主线：一条不可跳步的链

```
提问 │ ① 开跑前   命题成立？判据写死了？      不成立 / 没写 → 不开跑
     │ ② 执行中   一次只动一个变量            清单没写 / 双跑不一致 → 不开跑
     ─────────────────────────────────────────────────────
验证 │ ③ 出结果   按固定顺序验证              前一级不过 → 后一级不看
     │ ④ 呈现前   A 闸                        非零退出 → 阻断
     │ ⑤ 提交前   B 闸                        任一项不过 → 重审
     │ ⑥ 升级前   C 闸                        未双冻结 / 双跑不一致 → 阻断
     ─────────────────────────────────────────────────────
纠偏 │ ⑦ 收尾     落盘 + 残留清零             没落盘 = 没做
```

**任何一步跳过，后续结果不作数。**

## 1. 提问：开跑前

### 1.1 命题必须成立

答不出以下四问，**不开跑**：

| # | 问题 | 判定式 |
|---|---|---|
| 1 | 数据非空 | `len(x) > 0`、行数符合预期、唯一值 > 1 |
| 2 | 分母成立 | 先算 `n_eff` / 折数 / 是否单年独撑；`n_eff < 30` 标"样本不足" |
| 3 | 无标签中间量入模 | 准确率逼近 100% 即阻断 |
| 4 | 连带影响已列全 | 本次改动会连带改变的东西全部列出，答不出即停 |

- **空数据不得用于证伪任何命题。**
- **阈值判据与充分性判据必须分开过闸**——「表现如何」与「样本够不够」是两个问题。
- **行级统计不得用于因果推断。**

### 1.2 判据必须预注册

- **看到结果之前**，把成功/失败写成数字或区间。
- 允许改判据，但必须**在跑之前**改，并记录改了什么。
- **禁止**先看结果再定标准。

---

## 2. 提问：执行中

### 2.1 一次只动一个变量

- 每轮只改一个参数。
- 禁止同时改 Prompt、上下文与代码结构。
- 连带影响清单未写 → **不开跑**。

### 2.2 确定性验收

- 同机同代码**同配置双跑，CSV md5 必须 bit 级一致**；不复现即 bug（`WF_X_DETAIL=1` 列指纹定位）。
- **验收必须清缓存重跑**；同缓存双跑**不算**验收。
- **固定随机种子不构成**确定性证据。
- 跨日 / 跨机只比 lift / 护栏等决策指标，**禁止**逐行 diff CSV。
- **禁止取最好的一次当结论。**

### 2.3 措辞与呈现要求

→ 见 **AGENTS.md `## 🗣 回答规范`**（措辞 / 因果标注 / 判定式 / 先图后文 /
只留可 grep / `|` 不进表格）。AGENTS 每次会话自动加载，**此处不复述**。

## 3. 验证：出结果

### 3.1 判读顺序（不可颠倒）

```
⓪ 同一性：WF 的函数 = 生产的函数？训练时点 = 推理时点？被评估的概率 = 生产下单用的概率？
        ↓   （①~④ 问「这个数可不可信」，⓪ 问「这个数说的是不是我要的东西」）
① 绝对值异常（准确率 / IC / 概率饱和 / 分组符号一致性）
        ↓
② PBO < 0.5
        ↓
③ DSR ≥ 0.95
        ↓
④ 净IR CI 不跨 0   且   lift > 0
        ↓
⑤ 才谈仓位
```

**前一级不过，后一级不看。⓪ 不过，①~⑤ 全套不必跑。**

> **⓪ 为什么会排在最前**：三道闸全部作用在指标上，没有一道问「这个指标描述的是不是我要部署的
> 那个函数」。同一类错误已复发三次——三.28（PBO 0.43 / DSR 1.000 全过却是 100% 准确率假信号）、
> 三.57（PBO 当闸用，秤本身不可分辨）、三.60（闸全过，但 WF 描述的不是生产那个函数）。
> ⚠️ ⓪ 目前**无自动脚本**，靠人工逐项核对；详见 `REVIEW_GATES.md` 与 lessons 三.60。

执行（仓库根目录）：

```bash
python3 scripts/presentation_gate.py --input <csv> --horizon N
```

**非零退出即阻断。**

第 ① 级三条硬检查：

1. `Predict_Prob` 是否饱和成 0/1
2. 预测 UP 组 `Relative_Return`（= Actual_Return − HSI 未来收益，CSV 无此列须重建）**最大值 ≤ 0 即阻断**
3. 分组符号一致性

### 3.2 显著性

- 命中率 / 准确率 / lift 的显著性**必须按 Fold 聚类后检验**。
- **行级统计不得用于因果推断。**
- 未附聚类检验或复算证据的因果结论，一律标注为**仅判断**。

### 3.3 三种验证手段的使用规则

| 级别 | 手段 | 要求 |
|---|---|---|
| 最强 | 本地运行 + 单测 + 黄金数据比对 | 结果类**必须** |
| 中等 | 标注来源与推导，独立检索核对 | 引用类**必须**；**不得让 AI 自我背书** |
| 最弱 | 「指出你最可能出错的三处」 | **仅排查，不得作为唯一依据** |

- 三者只验「算得对不对」；「命题成不成立」由 §1.1 与 §3.1 负责。
- **规则一律落成脚本或可 grep 的清单，不得只写散文。**
- 含 `|` 的 shell 命令**一律放代码块，不进表格**。

## 4. 验证：⓪ 同一性 + 三道闸

| 闸 | 触发时机 | 执行 | 阻断条件 |
|---|---|---|---|
| **⓪ 同一性** | 任何指标作为结论输出前（**先于 A 闸**） | 四问：① 社区 ID 集合相等？② 列集合同源？（pkl ⊆ WF 可用列 + F1/HIBOR 两边都在 + 选择规则同源；**不要求逐字相等**，WF 每折重选恒不等）③ 训练时点 = 推理时点？④ 概率同源？ | 任一「否」。⚠️ `scripts/parity_check.py` **尚未实现**，当前人工核对；**且当前四问全部不通过**（lessons 三.60） |
| **A 呈现** | 任何指标作为结论输出前（**与有没有改动无关**） | `scripts/presentation_gate.py --input <csv> --horizon N` + 结论标注「适用范围：WF 内部 ✓ / 外推生产 ✗」 | 非零退出；**或适用范围未标注**（⚠️ 后者无工具强制，靠自觉） |
| **B 提交** | 任何代码 / 配置 / 文档改动后、commit 前 | `REVIEW_GATES.md` 9 项清单逐项过 | 任一项不过 |
| **C 升级** | 🟢 / 升配 / 加仓 / 改阈值前 | 双冻结 + 同配置双跑 **∧ ⓪ 通过** | md5 不一致，或取了最好一轮，或 **⓪ 不过** |

**B 闸首条**：改动完成后，像攻击对手一样攻击自己的改动，确认无问题才提交。

> **C 闸为什么加 ∧⓪**：md5 一致只证明「同一条路径可复现」，**不证明「两条路径相同」**。
> 2026-10-12 那 38 折复现的是一个**没人部署的函数**。

### 硬约束 2 —— 任何阈值 / 仓位变更后

```bash
grep -nE "仓位|放大|可升至|≤[0-9]+%|净IR [0-9]" docs/DEPLOYMENT.md README.md
```

**逐行判读**，确认没有与当前判定相反的**无条件现状建议**。
「🟢 升级 → 才可放大」这类**条件规则是正确的，不得删除**。

## 5. 纠偏：出错时

**Step 1 — 先备客观参照物**：完整报错日志、黄金数据集（人工校验无误的输入→输出）、官方规范。

**Step 2 — 诊断型 Prompt**（不得用猜测型）：

> "请在关键节点加入日志，输出中间过程的数据形态。运行后我把日志发给你，
> 请分析哪一步的数据转换与预想不符。"

- 定位后**删除全部临时日志**。
- 中间产物非空**必须先断言再分析**（`len(x) > 0`、列名存在、行数符合预期）。

**Step 3 — 对抗诊断**：

> "请扮演极其严苛的审核者，找出这个方案的 3 个潜在隐患或边界漏洞。"

- 产出**必须**落成脚本或可 grep 的清单，**不得**停留为口头结论。

---

## 6. 纠偏：落盘

- **临时脚本可以是一次性的，结论不能是。** 诊断 / 审计脚本跑完即删；
  判定与证据链必须写入单一真相源。
- 结论改动后：**全库过期残留 `grep` 清零 + 内链断链 0**。
- **没有落盘 = 没有做。**

## 7. 边界

按 [QUANT_SYSTEM_METHODOLOGY §6](QUANT_SYSTEM_METHODOLOGY.md)：**统计负责排除，判断负责选择**。
统计说不显著，**不得**改口说"其实显著"，只能降仓或不用。

以下情形 AI **只可辅助、不可决策**：

| 情形 | 兜底 |
|---|---|
| 指标作为结论输出 | **⓪ 同一性闸 → A 闸** |
| 代码 / 配置 / 文档改动 | **B 闸** |
| 🟢 / 升配 / 加仓 / 改阈值 | **C 闸** |
| 阈值 / 仓位变更后的文档 | **硬约束 2** |
| 结果无法运行、无法对照、无法抽检 | 按**不可信**处理 |
| 含密钥 / 依赖链未审计 | 安全评审后再合入 |
